# Парсер вакансий из Telegram

Личный бот собирает вакансии из Telegram-каналов выбранной папки аккаунта.
Источники проверяются каждые 30 секунд. Вакансии получают оценки, описания и категории,
повторные уведомления подавляются. Личные чаты HR из папки «Удаленки» используются
для статистики откликов по команде `/responses`.
Пример устройства Telegram-части приложения:
[paxanraul/tg-parser](https://github.com/paxanraul/tg-parser).

Настроены ваши критерии:

- удалённая работа;
- примерно 2–6 часов в день, объявления с большей занятостью отсекаются;
- фиксированный месячный оклад от 40 000 рублей без верхней границы;
- требуемый опыт не больше 3 лет: «1–3 года» допускается, «3–5 лет»,
  «от 4 лет» и «более 3 лет» отсекаются.

Любой подтверждённый месячный оклад от 40 000 рублей даёт полные баллы за оплату,
включая суммы выше 60 000. Остальные критерии проверяются независимо от зарплаты.
Гарантированная сумма ниже 40 000 отсекается, даже если с бонусами обещают больше.
Желаемые специальности и исключения пока не заданы.

## Проверка без Telegram

Нужен Python 3.11 или новее:

~~~powershell
python app.py --demo
~~~

После установки можно запустить **start.bat --demo**. Появятся оценки восьми
тестовых объявлений. В **demo-results.json** сохраняются подробные причины
решений. Это примеры, а не свежие вакансии из Telegram.

## Подключение на Windows

1. Откройте PowerShell в этой папке:

   ~~~powershell
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ~~~

   Скрипт создаёт виртуальное окружение, ставит зависимости, создаёт
   **.env** и **profile.json**, сохраняя существующие настройки.

2. В локальном **.env** заполните:

   - **TELEGRAM_API_ID** и **TELEGRAM_API_HASH** — из
     [my.telegram.org/apps](https://my.telegram.org/apps).
   - **BOT_TOKEN** — токен вашего нового бота от [@BotFather](https://t.me/BotFather),
     команда /newbot.
   - **OWNER_TELEGRAM_ID** пока оставьте пустым.

3. Выполните первый вход:

   ~~~powershell
   .\.venv\Scripts\python.exe app.py --login
   ~~~

   Введите номер телефона, код из Telegram и облачный пароль, если он установлен.
   Команда выведет ваш **OWNER_TELEGRAM_ID** — внесите его в **.env**.

4. Откройте своего бота в Telegram, нажмите **Start**, затем запустите
   **start.bat**. В чате с ботом:

   ~~~text
   /folders
   /folder Вакансии
   /scan
   /jobs
   ~~~

   Вместо «Вакансии» укажите название своей папки или её числовой ID из /folders.
   Первая фоновая проверка тоже загрузит до 100 последних сообщений каждого
   источника после выбора папки.

Парсер работает, пока компьютер включён, есть интернет и окно приложения открыто.
Остановка — Ctrl+C. Проверить заполнение настроек без соединения с Telegram:

~~~powershell
.\.venv\Scripts\python.exe app.py --check
~~~

Токены, код входа и файл сессии вводите только локально. Файлы **.env**
и **data/account.session** исключены из Git; сессия даёт доступ к аккаунту.

## Что приходит в бот

Бот автоматически отправляет только вакансии с оценкой **от 60/100 включительно**, которые
соответствуют остальным критериям. Можно повысить порог командой **/set score 70**;
значения ниже 60 не принимаются. Старые настройки с меньшим порогом автоматически
применяются как 60. Проверка действует и для очереди, и для **/show номер**.

Карточка содержит должность, категорию, компанию, оплату, локацию, формат работы
и тип занятости, если эти сведения есть в публикации. Краткое описание отдельными
строками показывает позицию, две основные задачи, ключевые требования и важные
условия (например, обучение или гибкий график), до 600 символов. Также сохраняются оценка **0–100**, причины
совпадения, неизвестные условия, дата и ссылка на оригинал.
Описание формируется локально из текста и распознанных фактов, без AI API и ключей.
Неуказанные условия не придумываются. Для Telegram ваш аккаунт автоматически пересылает оригинал в этот же
чат с вашим ботом: карточка приходит от бота, оригинал отображается как ваша
пересылка. Авторы вакансий сообщений не получают.

Если источник запретил пересылку, приходит карточка со ссылкой и описанием только
распознанных условий, без текста должности и задач. В подборках
с несколькими явно размеченными вакансиями бот отправляет только подходящий
пункт текстом, чтобы не присылать вместе с ним отклонённые пункты.

Повторные тексты и репосты подавляются. Отметки доставки сохраняются в SQLite.
Команда /show номер позволяет запросить повторную отправку. При обрыве связи
между отправкой и записью результата возможен единичный повтор.

## Статистика откликов по перепискам Telegram

После перезапуска бота нажми **«Статистика откликов»** или отправь:

~~~text
/responses
/responses 90
/responses all
/responses stats
/responses list
/responses list 2 all
/responses folder Удаленки
/responses help
~~~

`/responses` читает только личные чаты HR из папки **«Удаленки»** за последние 30 дней.
Личные переписки вне этой папки не анализируются и не попадают в сохранённую статистику.
Папка HR выбирается отдельно от папки каналов с вакансиями: `/responses folder название` или ID.
По умолчанию используется `RESPONSES_FOLDER=Удаленки`; выбор команды сохраняется между запусками.
Если нужная папка не найдена, бот сообщит об ошибке и не начнёт обход всего аккаунта.
Для папок с явно добавленными чатами сведения об участниках загружаются одним пакетным запросом.
Число меняет период (1–3650 дней), `all` читает всю доступную историю и может выполняться долго.
Бот сопоставляет текущие активные юзернеймы собеседника с контактами HR во всех сохранённых вакансиях
Telegram, включая старые, отклонённые и объявления из уже отключённых источников.
Для такого сопоставления сначала собери объявления через `/scan`.

Учитываются исходящие обращения о вакансии и отправка резюме; входящие предложения, пересланные
объявления и обычные приветствия не считаются откликами. Если у HR несколько вакансий, бот ищет
ссылку или должность в обращении, а для ответа с резюме — в сообщении собеседника за предыдущие сутки.
Должности объединяются по синонимам, сферы означают профессиональные направления работы.
Если объявление не найдено, распознанная по тексту должность помечается как предположение.
Неоднозначные обращения выводятся отдельно и не попадают в распределение должностей и сфер.

Одна вакансия у одного HR считается один раз, последующие сообщения не увеличивают число откликов.
Дата отклика — дата первого найденного обращения. Анализ ограниченного периода может не увидеть
первоначальный отклик в более старой переписке; `/responses all` уточняет такие даты.
`/responses stats` и `/responses list` показывают сохранённые результаты без обращения к Telegram;
у них также можно выбрать период: `/responses stats 90`, `/responses list 1 90`.
В списке видны дата, HR, должность, основание связи с вакансией и ссылка на объявление.
В отчёте указаны папка, число выбранных/проверенных чатов и прочитанных исходящих сообщений.
Если Telegram временно ограничил обновление или анализ уже идёт, `/responses` показывает
сохранённую статистику сразу. `/responses stats` всегда читает только локальную базу.
Отправка резюме в течение суток после обращения продолжает тот же отклик.
Анализ запускается только по команде. Тексты личных сообщений и файлы резюме не сохраняются в SQLite:
в ней хранятся идентификаторы, дата и результат сопоставления. Резюме не скачивается, внешняя AI-модель
не используется. Бот не пишет собеседникам.

Распознавание основано на локальных правилах, поэтому результат может требовать уточнения.
Старые юзернеймы, удалённые сообщения и недоступные переписки восстановить нельзя.
При ошибке доступа или ограничении Telegram отчёт отмечается как неполный. Найденные отклики
сохраняются даже из ещё не дочитанного чата; каждые 100 сообщений сохраняется прогресс.
Известные HR проверяются раньше остальных личных диалогов, фоновый сбор каналов на время анализа
ожидает своей очереди. Короткое ограничение (до 30 секунд, не более двух ожиданий за запуск)
бот пережидает автоматически. При более долгом или повторном ограничении повтори ту же команду
с тем же периодом после указанного ожидания: анализ продолжится с сохранённого места,
включая после перезапуска бота. История вакансий до запуска парсера
может отсутствовать; такие обращения останутся без связи с объявлением.

## Поиск по контакту HR

Отправьте боту `@recruiter_name`, `recruiter_name`, `https://t.me/recruiter_name`
или номер телефона HR. Можно отправить обычную карточку контакта Telegram с номером.
В меню добавлена кнопка **«Поиск по HR»** с подсказкой.

~~~text
@recruiter_name
+7 (999) 123-45-67
/hr @recruiter_name
/hr +79991234567
~~~

Поиск использует контакты из уже собранных объявлений Telegram. Регистр никнейма,
формат ссылки и оформление телефона не влияют на совпадение; российские номера
с `+7`, `8` и десятизначные мобильные номера приводятся к одному виду.
Ищется точный контакт: `@recruiter_name` не совпадает с `@recruiter_name_extra`.
Также можно искать по email, если он указан в объявлении.

Обычный поиск показывает все уникальные вакансии этого HR из активных источников:
Telegram за последние 72 часа. Включаются объявления, не прошедшие
ваши критерии, с явной пометкой. Каждая запись содержит позицию, краткое описание,
оплату при наличии, дату, оценку и ссылку на оригинал. Подходящую свежую вакансию
можно открыть обычной командой `/show номер`.

Все совпадения доступны страницами по 10, без ограничения подборки `/jobs` в 20 записей.
Бот показывает общее количество и команды «Ещё» / «Назад»:

~~~text
/hr @recruiter_name 2
/hr @recruiter_name all
/hr @recruiter_name all 2
~~~

Вариант `all` ищет по всей сохранённой истории, включая старые и отключённые
источники. Устаревшие вакансии помечаются **«Архив»**, отключённые источники —
**«Источник вне текущей подборки»**. Это ручной просмотр сохранённых данных;
автоматический сбор ТГ по-прежнему ограничен 72 часами. Если контакт не найден,
бот предлагает проверить историю или обновить базу командой `/scan`.

Поиск работает локально, в том числе во время паузы сбора. Он не меняет выбранный
раздел, критерии и отметки отправки вакансий. Ограничения защищённых источников
сохраняются. Индекс контактов для существующей базы создаётся автоматически при запуске;
платные API и дополнительные зависимости не нужны.

## Категории вакансий

Категория назначается только после прохождения существующих критериев:

1. **Content & Creative** — тексты, редактура, копирайтинг, сценарии, контент и SMM.
2. **Chat Support & Moderation** — переписка с пользователями, чат-поддержка и модерация.
3. **Management & Sales** — продукты, проекты, продажи, развитие бизнеса и работа с клиентами.
4. **Other / Uncategorized** — остальные подходящие вакансии, включая ввод данных.

Локальные правила учитывают русские и английские названия, синонимы и сочетания
действий с объектами в обязанностях. Явные обязанности могут перевесить название;
требования к навыкам, описание компании и преимущества не голосуют за категорию.
Это эвристический разбор без AI API: необычные формулировки могут попасть в группу 4.

**/tg** и кнопка **«Вакансии ТГ»** открывают вакансии Telegram.
**/jobs** показывает лучшие 20 результатов Telegram, сгруппированные по категориям.
**/jobs 1**, **/jobs 2**, **/jobs 3**, **/jobs 4** показывают до 20 вакансий выбранной
группы; **/categories** выводит названия и команды. Просмотр категории не меняет
фильтры и уведомления. Группа 4 доступна на тех же условиях, что и остальные.
После перезапуска существующие недавние вакансии получают новые описания и категории;
отметки доставки сохраняются, повторной рассылки из-за обновления не происходит.

## Команды и изменение характеристик

Названия групп в списках, справке по категориям и карточках выделяются **жирным**.
Форматирование передаётся сущностями Telegram; символы в названиях вакансий и
тексте объявлений сохраняются буквально.

### Вакансии специалистов из Telegram

**/pro** (кнопка **«Вакансии специалистов»**) показывает отдельную подборку из
той же выбранной Telegram-папки за последние 72 часа. Учитываются все собранные
объявления, включая отклонённые личными фильтрами. Нужны явно указанная удалённая
работа и требования к опыту или конкретным профильным навыкам. Ограничений по
часам, зарплате, фиксированному окладу и стажу нет; `/profile` и `/set` эту подборку
не меняют. Вакансии с обучением с нуля исключаются. Если формат не указан,
объявление не попадает в `/pro`.

Группы: **1 — Разработка и IT**, **2 — Аналитика**, **3 — Маркетинг**,
**4 — Продажи**, **5 — Продукты и проекты**. В выдаче показываются требования,
которые послужили основанием для отбора. Отбор выполняется локальными правилами:
необычные названия и формулировки могут не распознаться.

- `/proscan` — заново проверить до `HISTORY_LIMIT` последних сообщений каждого
  источника (по умолчанию 100), отобрать свежие вакансии и сразу показать подборку.
- `/pro` — все группы из уже собранной базы; `/pro 2` — только аналитика.
- `/pro page 2` — следующая страница; `/pro 3 page 2` — страница группы маркетинга.
- `/prohelp` — группы и условия отбора.

В выдаче до 10 объявлений на странице, без повторов; внутри группы — сначала
новые. Фоновое чтение той же папки также пополняет подборку, но отдельные
уведомления о специалистах не рассылаются. `/proscan` соблюдает `/pause`,
сохранённые позиции чтения и ограничения Telegram. Защищённые источники
показываются ссылкой без раскрытия текста. Оригиналы вакансий открываются по
ссылкам в подборке.

| Команда | Действие |
|---|---|
| /pro, /pro 1 (2, 3, 4, 5) | Удалённые вакансии специалистов; все группы или выбранная |
| /proscan | Обновить подборку специалистов из текущей Telegram-папки |
| /prohelp | Условия новой подборки |
| /tg | Вакансии Telegram |
| /tg 1 (2, 3, 4) | Категория вакансий Telegram |
| /folders | Папки вашего аккаунта |
| /folder название или /folder 2 | Выбрать папку |
| /sources | Каналы и группы папки и ошибки доступа |
| /scan | Заново проверить последние 100 сообщений каждого источника |
| /jobs | Лучшие 20 вакансий Telegram по текущим критериям, по категориям |
| /jobs 1 (2, 3, 4) | Лучшие 20 вакансий выбранной категории |
| /categories | Все четыре категории и команды просмотра |
| /show 12 | Карточка и оригинал вакансии №12 |
| /profile | Показать критерии |
| /set ... | Изменить критерии |
| /pause, /resume | Остановить или возобновить сбор и уведомления |
| /stats | Статистика, время проверки и последняя ошибка |
| /help | Инструкция и примеры |

Примеры настройки прямо в боте:

~~~text
/set hours 2 6
/set salary 40
/set experience 3
/set unknown off
/set score 70
/set remote on
/set fixed on
/set keywords Excel, переписка, поддержка
/set exclude холодные звонки, продажи
/set exclude clear
/set keywords clear
~~~

Изменения сохраняются в **profile.json**, загруженные объявления пересчитываются.
Можно редактировать файл вручную: изменения подхватятся при следующей проверке.
Команда **/set salary 40** (или **/set salary 40000**) задаёт только минимальный
оклад. Верхняя граница из старых настроек больше не учитывается.
Желаемые слова дают небольшой бонус; исключённые слова блокируют вакансию.

## Как работает оценка

Фильтр бесплатный и локальный, без AI API. Он распознаёт распространённые русские
и английские формулировки; понимание произвольного текста ограничено.
Баллы: формат работы — 30, часы — 25, зарплата — 25, опыт — 15,
желаемые слова — 5. Неизвестные условия дают меньше баллов.
Это оценка совпадения по тексту, а не вероятность найма.

Неполные объявления с оценкой от 60 могут попасть с жёлтой пометкой
**«Нужно уточнить»**. При оценке ниже 60 они не отправляются.
Для строгого режима отправьте **/set unknown off**.
«До 60 тысяч», почасовая оплата и другая валюта не считаются подтверждённым
месячным окладом в рублях. Зарплата без слов «оклад»/«фикс» тоже требует
уточнения вида оплаты. Отсутствующий опыт не считается подтверждением «без опыта».
Опыт, явно отмеченный как желательный или преимущество, не считается обязательным.

Подборки разделяются по повторяющимся заголовкам «#вакансия», «Вакансия:»,
«Vacancy:». Без явных границ несколько вакансий могут прочитаться как одна.
Текст картинок и голосовых сообщений не распознаётся; подписи к медиа читаются.
Спорные условия сверяйте с оригиналом.

## Папки, история и восстановление

Используется Telegram API [dialog filters](https://core.telegram.org/api/folders):
обычные и импортированные папки, явно добавленные и закреплённые каналы,
категории «все каналы»/«все группы», исключения. Личные переписки не сканируются.
Если в папке включено «все каналы», источниками будут все каналы, попавшие
в неё по правилам Telegram.

Состав обновляется каждые 5 минут и перед /scan. Переименование не влияет
на выбранную папку: хранится её ID. Удалённая папка отключает прежние источники.
Приложение не вступает в новые каналы; аккаунт должен уже иметь к ним доступ.

Из Telegram-папки рассматриваются публикации только за последние **72 часа**,
с точностью до времени публикации, а не календарных дней. У пересланных сообщений
учитывается также дата оригинала. Ограничение действует для загрузки, очереди,
подборок и `/show`; сохранённые старые записи доступны только по явному запросу
истории `/hr контакт all`.
Параметр `MAX_POST_AGE_DAYS` может сократить этот срок, но не увеличить его выше трёх суток;
при первом подключении читаются последние 100 сообщений каждого источника. После перезапуска
пропуски дочитываются по сохранённой позиции порциями по 200 за цикл.
Ручной /scan не перескакивает через необработанную историю фоновой проверки.
Изменения старых публикаций проверяются командой /scan.

Повторы из разных чатов сравниваются локально: название позиции, описание,
задачи, компания и контакты HR (Telegram, email, телефон). Форматирование,
регистр и рекламные подписи каналов не мешают сравнению. Небольшие изменения
описания при совпадающем контакте тоже распознаются. Один контакт HR не объединяет
разные позиции; без совпадающего контакта требуется почти дословный текст.
Разные явно указанные контакты или компании считаются отдельными объявлениями.
Сравнение консервативное: сильно переписанная вакансия может остаться отдельной.

Копии сохраняются с общим ключом и отметкой отправки в SQLite, поэтому повторные
проверки и перезапуск не рассылают их заново. В списках показывается одна актуальная
копия из активных источников. Старая база обновляется автоматически при запуске,
с сохранением номеров вакансий и отметок доставки. Платные API и новые зависимости не нужны.

| Параметр в .env | Значение по умолчанию |
|---|---|
| TELEGRAM_FOLDER | Выбор через бота |
| POLL_SECONDS | 30 секунд |
| HISTORY_LIMIT | 100 сообщений при первом подключении и /scan |
| MAX_POST_AGE_DAYS | Не более 3 суток |
| MAX_NOTIFICATIONS_PER_CYCLE | 10 вакансий; остальные остаются в очереди |

Бот принимает команды только от владельца в личном чате. Пересланные сообщения
не выполняются как команды. Личный аккаунт должен совпадать с OWNER_TELEGRAM_ID.
Для одного аккаунта запускайте один экземпляр приложения.

## Тесты

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe app.py --demo
~~~

Тесты используют имитацию Telegram, не обращаются в сеть и не отправляют сообщений.
Проверяются фильтр, папки, изменение критериев, команды владельца, повторы,
сохранение позиции, пересылка и ограничения защищённых источников, четыре категории,
неоднозначные названия, описания и просмотр категорий без повторной доставки,
пагинация, статистика откликов из папки HR, миграция старой базы и одновременные
проверки источников без дублирующихся уведомлений.
